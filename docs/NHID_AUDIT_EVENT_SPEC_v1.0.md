**Date**: 2026-07-30  
**Status**: ✓ FINAL  
**Version**: 1.0 (Frozen for v1.1 release)  
**Governance**: Compliant with HIPAA audit trail requirements (45 CFR §164.312(b))  
**Retention**: 7 years minimum (configurable to customer DPA)  

---

## Purpose

This specification defines the schema, immutability requirements, and lifecycle management for audit events generated by NHID-Clinical governance enforcement. Audit events create a tamper-evident record of:
1. **Governance decisions** (conformant/deny actions)
2. **Rule violations** (which compliance boundary was crossed)
3. **Sensitive data access** (PHI accessed during call)
4. **System state** (agent behavior, escalation outcomes)

Audit events enable:
- **Compliance auditing** (HIPAA, state telehealth laws)
- **Incident investigation** (trace root cause of false denial or missed violation)
- **Regulatory disclosure** (respond to breaches or regulatory inquiries)

## Audit Event Schema v1.0

### Core Event Structure

```json
{
  "audit_event_id": "string (UUID v4, unique identifier)",
  "event_type": "enum (GOVERNANCE_DECISION, RULE_VIOLATION, DATA_ACCESS, ESCALATION_ACTION)",
  "timestamp": "RFC3339 (UTC, millisecond precision)",
  "source_system": "NHID-Clinical v1.1",
  "correlation_id": "string (links to originating governance request)",
  
  "governance_context": {
    "session_id": "string (conversation/call session identifier)",
    "turn_index": "integer (position in conversation)",
    "actor_id": "string (system identifier, not human PII)",
    "counterparty_type": "enum (human_operator, automated_system, hybrid)",
    "healthcare_domain": "enum (authorization, claims, prior_auth, eligibility)"
  },
  
  "decision_payload": {
    "action": "enum (ALLOW_DATA, DENY_DATA, ESCALATE)",
    "conformant": "boolean (true = passed all rules)",
    "rules_evaluated": ["IDG-01", "PDX-01", "DBC-01", "EIT-01", "ATR-01"],
    "violations_detected": [
      {
        "rule_id": "string",
        "severity": "enum (critical, high, medium)",
        "description": "string (human-readable violation description)",
        "trigger_field": "string (which input triggered the rule)"
      }
    ],
    "cas_score": {
      "score": "float (0.0–1.0, Call Authorization Score)",
      "tier": "enum (Denied/Degraded, Authorized, Priority)",
      "badge_eligible": "boolean or null"
    }
  },
  
  "phi_access_log": {
    "phi_requested": ["array of phi field identifiers"],
    "phi_accessed": ["array of phi actually transmitted"],
    "access_timestamp": "RFC3339 (when PHI was accessed)",
    "access_reason": "string (why PHI was accessed)"
  },
  
  "escalation_log": {
    "escalation_requested": "boolean (did caller request escalation?)",
    "escalation_timestamp": "RFC3339 (when escalation was requested/processed)",
    "escalation_outcome": "enum (honored, denied, deflected, ignored, redirected)",
    "target_type": "enum (human_agent, queue, ivr_menu, service_tier)"
  },
  
  "system_metadata": {
    "engine_version": "string (1.1.0)",
    "adapter_type": "string (vapi, twilio, custom, synthetic)",
    "request_id": "string (unique per API call)",
    "execution_time_ms": "integer (milliseconds to evaluate)",
    "replay_mode": "enum (live, test, replay)",
    "external_calls_cached": "boolean (were external API calls mocked?)"
  }
}
```

## Event Types & Classification

### 1. GOVERNANCE_DECISION Events

**Triggered**: After policy engine evaluation completes (every turn)

**Purpose**: Record the action taken and reasons

**Key Fields**:
- `action`: ALLOW_DATA | DENY_DATA | ESCALATE
- `conformant`: boolean
- `violations_detected`: array of rule violations (empty if conformant)
- `cas_score`: authorization tier

**Example**:
```json
{
  "audit_event_id": "evt_20260730_abc123",
  "event_type": "GOVERNANCE_DECISION",
  "timestamp": "2026-07-30T10:15:23.456Z",
  "correlation_id": "call_auth_req_001",
  "decision_payload": {
    "action": "DENY_DATA",
    "conformant": false,
    "rules_evaluated": ["IDG-01", "PDX-01", "DBC-01", "EIT-01"],
    "violations_detected": [
      {
        "rule_id": "IDG-01",
        "severity": "critical",
        "description": "Automated system identity not disclosed before PHI request",
        "trigger_field": "identity_assertion_text"
      },
      {
        "rule_id": "PDX-01",
        "severity": "critical",
        "description": "PHI accessed before disclosure gate was satisfied",
        "trigger_field": "phi_accessed"
      }
    ]
  }
}
```

### 2. RULE_VIOLATION Events

**Triggered**: When a specific rule is violated (optional; can be derived from GOVERNANCE_DECISION)

**Purpose**: Detailed rule-level audit trail for compliance investigation

**Classification**:
- **IDG-01 violations**: Missing or vague identity disclosure
- **PDX-01 violations**: Timing gate failure (PHI before disclosure)
- **DBC-01 violations**: Deceptive behavior detected
- **EIT-01 violations**: Escalation deflection/denial
- **ATR-01 violations**: Audit trail recording failure (Phase 2)

### 3. DATA_ACCESS Events

**Triggered**: When PHI is requested or transmitted

**Purpose**: Comply with HIPAA audit trail requirements (45 CFR §164.312(b))

**Key Fields**:
- `phi_requested`: List of fields requested by agent
- `phi_accessed`: List of fields actually returned
- `access_reason`: Why PHI was accessed (auth lookup, claims verification, etc.)

**Example**:
```json
{
  "audit_event_id": "evt_20260730_def456",
  "event_type": "DATA_ACCESS",
  "timestamp": "2026-07-30T10:15:25.100Z",
  "phi_access_log": {
    "phi_requested": ["member_id", "date_of_birth", "npi"],
    "phi_accessed": ["member_id"],
    "access_timestamp": "2026-07-30T10:15:25.100Z",
    "access_reason": "Authorization eligibility check"
  }
}
```

### 4. ESCALATION_ACTION Events

**Triggered**: When escalation is requested or outcome determined

**Purpose**: Track escalation paths for compliance and customer support

**Key Fields**:
- `escalation_outcome`: honored | denied | deflected | ignored | redirected
- `target_type`: Where escalation was routed

## Storage & Immutability Requirements

### Append-Only Log Guarantee

**Requirement**: Audit events MUST be written to an append-only log structure. No modification, deletion, or backfilling is permitted after write.

**Implementation Options**:

#### Option A: AWS CloudWatch Logs (Recommended for Pilot)
```
Log Group: /nhid-clinical/audit-trail
Log Stream: {session_id}-{date}
Retention: 7 years (configurable per customer DPA)
Immutability: Native AWS Logs append-only guarantee
Tamper Detection: CloudTrail integration for log access audit
Access Control: IAM policy restricts audit log reads to compliance role
```

#### Option B: Amazon S3 (Object Lock)
```
Bucket: nhid-audit-trail-{environment}
Object Lock Mode: GOVERNANCE (7-year retention, immutable)
Partitioning: s3://nhid-audit-trail/{yyyy}/{mm}/{dd}/{session_id}.jsonl
Tamper Detection: S3 event notifications on read/delete attempts
Access Control: Deny DeleteObject and PutObject ACL changes via bucket policy
```

#### Option C: Custom Append-Only Database
```
Schema: audit_events table with:
  - PRIMARY KEY (audit_event_id)
  - CHECK (event_timestamp IS NOT NULL)
  - CONSTRAINT no_update: ON UPDATE RAISE(FAIL)
  - CONSTRAINT no_delete: ON DELETE RAISE(FAIL)
Replication: Read-only replica for compliance team queries
Tamper Detection: Database access logs + transaction log verification
```

### Retention Policy

**Minimum Retention**: 7 years from event creation  
**Rationale**: HIPAA audit trail (45 CFR §164.312(b)) + statute of limitations for healthcare fraud

**Storage Lifecycle**:
- **0–1 year**: Hot storage (immediate query access for incidents)
- **1–7 years**: Warm storage (annual compliance reviews, regulatory audits)
- **7+ years**: Delete or archive per customer agreement

**Compliance Note**: If customer DPA specifies longer retention (e.g., 10 years), honor customer requirement.

### Tamper-Evidence Features

**Feature 1: Hash Chain** (Optional, High Security)
```
Each audit event includes:
  "previous_event_hash": "sha256 hash of previous event"
  "event_hash": "sha256 hash of current event (excluding this field)"

Verification: Recompute hash chain; break indicates tampering.
```

**Feature 2: Cryptographic Signing** (Optional, High Security)
```
Audit events signed with KMS key:
  "kms_key_id": "arn:aws:kms:us-east-1:123456789:key/12345678"
  "signature": "base64-encoded HMAC-SHA256 signature"

Verification: KMS verify operation; fails if tampered.
```

**Feature 3: Immutability Guarantee** (Required)
```
All implementations (CloudWatch, S3, Database) must guarantee:
  - Write once, never modify
  - No deletion of audit events
  - Append-only semantics enforced by storage layer
  - Audit trail of access attempts (who queried audit logs, when)
```

## Audit Event Lifecycle

### 1. Generation (Synchronous)
```
Policy Engine evaluation completes
  ↓
Create GOVERNANCE_DECISION event (synchronous)
  ↓
If violations exist: create RULE_VIOLATION events
  ↓
If PHI accessed: create DATA_ACCESS event
  ↓
If escalation involved: create ESCALATION_ACTION event
```

**SLA**: Audit events generated within same request cycle (< 100ms latency added)

### 2. Persistence (Asynchronous)
```
Audit event created in memory
  ↓
Enqueue to audit logger (async queue)
  ↓
Audit logger writes to append-only store
  ↓
Acknowledge write success (or log failure)
```

**SLA**: Audit events persisted within 5 seconds (configurable)

### 3. Query & Compliance (On-Demand)
```
Compliance officer needs to audit a session
  ↓
Query audit log: SELECT * WHERE session_id = '...' AND timestamp > '2026-06-01'
  ↓
Retrieve events in chronological order (sorted by timestamp)
  ↓
Generate compliance report or incident timeline
```

**Access Control**: Read-only access to audit logs; restricted to compliance/security roles via IAM

## Compliance Mappings

### HIPAA 45 CFR §164.312(b) — Audit Controls

**Requirement**: Implement hardware, software, and procedural mechanisms that record and examine healthcare information system activity.

**NHID-Clinical Compliance**:
- ✓ Record governance decisions (every policy evaluation)
- ✓ Record PHI access (who accessed what, when)
- ✓ Record escalation outcomes (audit trail of human involvement)
- ✓ Append-only storage (tamper-evident)
- ✓ 7-year retention (meet minimum requirement)
- ✓ Access controls (restrict reads to compliance role)

### State Telehealth Requirements

**Example: California Telehealth Privacy Law (AB 375)**

**Requirement**: Maintain audit trail of automated system interactions with PHI.

**NHID-Clinical Compliance**:
- ✓ Discloses when AI/automated system is present (IDG-01 rule)
- ✓ Logs all PHI access attempts (DATA_ACCESS events)
- ✓ Logs escalation outcomes (ESCALATION_ACTION events)
- ✓ Supports regulatory inquiry (audit log export by date range)
