# Patient Access Fixtures (candidate)

Hand-authored scenarios for the candidate proposal in
[`../../docs/proposals/patient-access-authorization.md`](../../docs/proposals/patient-access-authorization.md):
the patient- and record-level access check (candidate ACC-01).

**Status:** prototype, opt-in, inside PDX-01 · **Added:** 2026-11-01 · **Measured:** 20/20 expected results reproduced (2026-11-08)

> **What is measured.** `src/record_access.py` reproduces the expected
> `access_authorization` result of all 20 scenarios (`tests/test_record_access.py`). That
> is a check that the prototype matches hand-authored expectations. It is not a detection
> rate, it was not run against any payer's records, and **no detection percentage is
> published or implied**.
>
> **Own denominator.** This set is separate from, and never pooled with, the v1 or v2
> Governance Evaluation Corpus, the Voice-Stress corpus or the
> `verification-nonverbal` fixtures. It is not a pinned baseline.

## How the file is made

`scenarios.json` is generated by `scripts/build_patient_access_fixtures.py`. The script
refuses to write a scenario that breaks the proposal's invariants:

1. **Per-operation binding**: eligibility binds member + DOB + eligibility request,
   claim status member + claim, prior auth member + authorization case.
2. **Payer-defined basis**: a pass needs a `relationship_basis` the assumed payer policy
   recognizes for that operation; `UNKNOWN` never passes and always escalates.
3. **Minimum necessary upstream**: no ACC-01 minimum-necessary check; when PDX-01 or
   VER-01 fails, ACC-01 is `not_assessable`.

It also enforces the two decisions (payer-verified appointment for new patients; linked
claims only), `measurement_status: not_yet_measured`, fictional NPIs and HMAC
placeholders. `--check` verifies the committed file.

## Record shape

Per scenario: `operation`, `expected` (four-result vocabulary, including `ACC-01`),
`expected_outcome` (existing ladder), `measurement_status`, `relationship_basis`,
`resource_binding` (operation-specific type and an HMAC placeholder), `delegated_scope`,
`payer_record` (what the payer's own systems hold; NHID never asserts it), and v1 corpus
turns with a `healthcare_governance` block that validates against the trace schema.
