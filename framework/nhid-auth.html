In short

v1.3 establishes that the caller said it was automated. NHID-Auth is the optional next layer: a signed delegation from a provider that a payer can verify offline, so the caller's authority to ask is checked rather than asserted.

It is a reference implementation for review, with no production issuers and no independent security audit.

Problem

The gap it closes

NPIs are public. Disclosure does not prove authorization.

01 / 09

NPIs are public. A caller can state one truthfully and still have no relationship to the organization it names. Behavioral controls establish that a caller disclosed itself as automated; they cannot establish that it was ever delegated authority to act for the provider it claims.

NHID-Auth addresses that with signed delegation rather than a registry or a gatekeeper. A provider signs a statement binding an agent’s public key to an NPI and a bounded scope. The receiving side verifies that signature offline — no lookup, no central authority, no service to call.

Mechanism

How it works

Five steps, none of which pass through NHID-Clinical.

02 / 09

  1. Provider signs a delegation

    The provider organization holds a key pair and signs a passport binding an agent public key to its NPI, a purpose, a scope, and an expiration.

  2. Agent presents the passport

    The AI agent carries the signed passport into the call alongside its behavioral disclosure.

  3. Receiver verifies offline

    Ed25519 signature verification against a trust anchor the receiver configured itself. No network call to NHID-Clinical, no registry lookup, no published-key directory, no dependency on us.

  4. Scope is enforced

    An agent delegated for eligibility checks cannot use the same passport to pursue claims appeals. Scope is a precondition, not a suggestion.

  5. Expiration and revocation

    Passports carry an expiry. A provider revokes by rotating keys or publishing a revocation, without coordinating with any third party.

Properties

Design properties

03 / 09
Property01

No registry, no gatekeeper

Verification is a signature check. NHID-Clinical is not in the trust path and cannot become a chokepoint.

Property02

Offline verifiable

Works when the network does not. Nothing about verification requires reaching an external service in real time.

Property03

Bounded by construction

Scope and expiration are fields in the signed payload, so an over-broad or stale passport fails verification rather than relying on policy.

Property04

Open reference code

The implementation is public in the repository under Apache-2.0; the format it implements is CC BY 4.0. Fork it, port it, or write your own against the format.

NHID-Auth v2 is a published open reference implementation, not a deployed identity infrastructure. There are no production issuers yet. It documents a workable approach to delegated agent authority and invites implementers to break it.

Release

NHID-Auth v2: cryptographic agent identity

v1.3 establishes behavioral disclosure. v2 addresses what v1.3 cannot.

04 / 09

v2 verifies that an AI agent is actually authorized by the provider it claims to represent. NPIs are public via NPPES — any caller can present a real one. v2 makes that insufficient.

Released June 2026 (code Apache-2.0, document CC BY 4.0). Reference implementation in src/agent_identity.py, exercised by tests/test_identity.py, tests/test_dlg01_delegated_authority.py and tests/test_trust_anchor.py. The license permits any use; the maturity does not. This is a reference implementation for technical exploration and review — not independently security audited, with no production issuers, and not a substitute for an organization’s own identity and access controls. As of v1.3 final, this is also wired into the hosted conformance API — not just a standalone library — via POST /v1/identity/verify-passport and POST /v1/identity/revoke-passport, with durable revocation that survives across stateless invocations.

Context

Where v2 sits in the trust stack

One layer in a stack that starts at a real gap and ends at a healthcare-native audit trail.

05 / 09

v2 is one layer in a stack that starts at a real gap (no cross-org NPI authorization exists today) and ends at a healthcare-native audit trail. Layers 2–4 are NHID-Clinical's contribution; Layer 3 (this page) is optional.

Reference Architectural model of how the layers relate. Layer 2 is specified and implemented in this repository; layer 3 is released as a separate document; layers 1, 4 and 5 are existing standards and are not provided by NHID-Clinical.

Contents

What the reference implementation contains

06 / 09
  • ISSUE

    Provider-issued agent credentials

    An agent's identity is signed by the provider organization it acts for, with the provider's 10-digit NPI bound into the credential. A valid credential requires the provider's private key — something public NPI data cannot produce.

  • SCOPE

    Scoped, time-limited authorization

    Agents carry only the operations their provider granted (eligibility, claim status, prior authorization). Credentials expire on a short TTL. Delegation can be narrowed, never expanded — scope escalation is rejected at verification.

  • REVOKE

    Immediate withdrawal

    A provider can revoke a compromised or decommissioned agent; the next verification fails. Revocation works per-agent or per-delegation. No central authority required.

  • BIND

    Call binding and out-of-band verification

    Credentials can be bound to a specific call session, preventing replay across calls. All checks happen via API, not in the voice channel — no latency added to the call. v1.3 behavioral controls run unchanged alongside the v2 layer.
